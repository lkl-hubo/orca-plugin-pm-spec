# LKL-PMStudio 需求中心产品经理使用手册

本手册面向非开发背景的产品经理（PM），每一步均写明在哪个界面、点击哪里、填写或复制什么内容、以及看到什么算成功。

---

## 开始前的 2 项准备

1. **确认工作区在本机电脑上**：需求中心 v1 仅支持本机文件夹或本机 Git 仓库（不支持 SSH 远程服务器或远程容器工作区）。
2. **确认已启用「需求中心」插件**：
   - 在 **LKL-PMStudio 桌面端** 窗口左下角打开「设置」→ 点击左侧菜单「插件」。
   - 在已安装/内置插件列表中找到 **需求中心（`lkl.pm-spec`）**，确认开关为已启用（首次启用如有权限批准弹窗，点击「批准并启用」）。
   - **看到什么算成功**：LKL-PMStudio 右侧边栏出现「需求中心」图标，窗口底部状态栏显示「需求中心」。

---

## 第一步：打开工作区并初始化（生成 `pmspec.json`）

1. **在哪操作**：LKL-PMStudio 主窗口左侧边栏。
2. **怎么点**：
   - 选中你要存放 PRD 规格的工作区（或者点击左侧边栏「打开文件夹」选中电脑上的一个本机文件夹，例如 `/Users/你的名字/specs/merchant-platform`）。
   - 点击右侧边栏的 **「需求中心」** 图标打开面板。
3. **点击初始化**：
   - 如果该文件夹还没有初始化过，面板会显示 **「初始化规格工作区」** 按钮。
   - 点击 **「初始化规格工作区」**。
4. **看到什么算成功**：
   - 点击后 100 毫秒内按钮进入加载转圈状态并禁用（避免重复点击）。
   - 完成后工作区根目录生成 `pmspec.json`（若为 Git 仓库，`.gitignore` 会自动追加 `.pmspec/runs/` 与 `.pmspec/reviews/`）。
   - 右侧面板切换为规格列表界面，显示空列表提示和 **「新建规格」** 按钮。
5. **配置项目代码仓与签核角色（建议此时完成）**：
   - 在左侧文件树点击打开根目录的 `pmspec.json`，把以下字段改成自己项目的信息并按 `Cmd + S`（Windows 按 `Ctrl + S`）保存：
     - `product`：填写你的产品线名称，例如 `"收单商户平台"`。
     - `codeRepos`：把研发业务代码仓在本机的路径填进去（支持相对 `pmspec.json` 的路径如 `"../merchant-api"`，或完整绝对路径），`key` 用小写字母和连字符，例如 `"merchant-api"`。不需要 AI 对照代码时可保留为空数组 `[]`。
     - `roles`：填写产品内出现的全部业务角色，例如 `["商户管理员", "商户操作员", "运营", "系统"]`。
     - `review.requiredSignoffRoles`：从 `"产品"`、`"研发"`、`"测试"`、`"业务"`、`"风控"`、`"其他"` 中挑选必须签核才能定稿的角色，例如 `["研发", "测试"]`。

## 第二步：新建需求并编写结构化内容

1. **在哪操作**：LKL-PMStudio 右侧「需求中心」面板顶部。
2. **怎么点**：
   - 点击 **「新建需求」** 按钮（默认会自动预填 `REQ-YYYYMMDD-01` 格式编号，可直接使用）。
   - 确认或修改两个字段：
     - **需求 ID**：支持 2～64 位中文、字母、数字、连字符 `-` 或下划线 `_`（不能以 `-`/`_` 开头或使用 Windows 保留设备名，例如 `商户自助退款`、`refund-v2`、`PAY-REFUND-001`）。
     - **需求标题**：2～80 个字，例如 `商户自助退款`。
   - 点击 **「创建」**。
3. **看到什么算成功**：
   - 工作区下自动生成 `specs/PAY-REFUND-001/spec.md` 文件（已自动填入头信息与 7 个标准章节模板）。
   - 窗口中间编辑器自动打开该文件，右侧「需求中心」列表出现 `PAY-REFUND-001` 条目（状态为 `draft`）。
4. **编写要点**（完整语法见 [spec-format-v1.md](./spec-format-v1.md)）：
   - **需求与验收标准**：在 `## 需求明细` 下写 `### REQ-001 [P0] 需求标题`，每条需求下写 `- AC-001-01：假如 <前置条件>，当 <触发动作>，那么 <预期结果>`（例如 `- AC-001-01：假如 订单状态为「已支付」，当 商户提交退款，那么 系统创建退款单`，不要出现“尽快、及时、适当、左右、支持多种”等模糊词）。
   - **引用研发代码**：如果明确知道代码位置，可写 `@code(merchant-api:src/refund/RefundController.java#L40-L58)`，系统会自动核对路径和行号是否存在。
   - **状态机与埋点**：在 `pmspec-states` 和 `pmspec-events` 代码块内按 YAML 格式填写状态和事件。

## 第三步：运行确定性校验（Lint）并把错误清零

1. **何时自动运行**：打开规格详情页时自动运行一次；每次保存 `spec.md` 后约 0.8 秒也会自动刷新。
2. **手动触发方式**（任选一种）：
   - 在右侧「需求中心」点击进入 `PAY-REFUND-001` 详情页 → 切换到 **「校验」** 页签 → 点击 **「重新校验」**；
   - 或者在 LKL-PMStudio 按快捷键 `Cmd + Shift + P`（Windows 按 `Ctrl + Shift + P`）打开顶部命令面板 → 输入 **「需求中心：校验当前需求」** 后按回车。
3. **看懂结果**：
   - 每条校验结果分为 **错误（error，红色）** 和 **警告（warning，黄色）**，并附带具体行号与「修复建议」。
   - 点击列表中的任意一条问题，中间编辑器会自动光标跳转到对应行。
4. **看到什么算成功**：
   - 窗口底部状态栏更新为 `PAY-REFUND-001 · 0 错误 · 0 警告`（或允许保留少量非阻断警告，但**错误数必须为 0** 才能发起 AI 预检和保存快照）。

## 第四步：发起 AI 现状感知预检（含预检前检查代码仓状态）

AI 预检会拉起一个智能体帮你逐条对照研发代码检查逆向流程、幂等、并发、权限和边界遗漏。

### 4.1 预检前必做提示：检查关联代码仓的 `git status`

在点击预检之前，如果你在 `pmspec.json` 关联了本机业务代码仓（例如 `../merchant-api`），建议先确认代码仓没有未清理的临时改动，避免把你原本改到一半的文件当成“AI 预检改动了代码”：

1. 在 LKL-PMStudio 顶部菜单或终端面板打开业务代码仓目录的终端。
2. 复制粘贴并运行以下命令：

```bash
git status
```

3. **看输出怎么处理**：
   - 如果输出包含 `nothing to commit, working tree clean`（工作区干净），直接进入下一步即可。
   - 如果列出有未提交文件，建议先告知相关研发或使用 `git stash` 暂存，或者记录下这些原本就存在的文件名以便事后核对。

### 4.2 在面板发起预检

1. **前提检查**：
   - 当前规格校验 **0 个错误**；
   - 所选智能体已在 LKL-PMStudio 中启用并完成登录（默认使用内置 `pi`，并自动共享宿主拉卡拉 AI 网关与智能体登录态；如需切换，打开「设置」→「插件」→「需求中心」修改 `reviewAgent`）。
2. **在哪操作**：右侧「需求中心」→ 进入目标规格详情页 → 切换到 **「AI 预检」** 页签。
3. **怎么点**：点击 **「发起预检」** 按钮（按钮随即禁用防重点击）。
4. **看到什么算成功**：
   - 页签立即显示进度条与「智能体运行中」，系统会在后台终端拉起智能体执行只读检查（最长等待 `reviewTimeoutMinutes`，默认 15 分钟）。
   - 如果页面顶部出现**黄色提示条**「本次预检未能启用只读保护，已改为事后改动检测」，表示当前智能体或会话未进入强制拦截模式（例如选用了 `opencode` 等非 `pi` / `claude` 智能体），预检仍正常执行，并在结束后由插件自动比对前后代码仓变化。
   - 等待完成后，状态变为 **「已完成」**。
5. **异常警惕与处理发现**：
   - 如果页面出现**红色横幅**提示代码仓在预检期间被改动（状态 `tainted`），插件**绝不会自动回滚你的文件**，请立即打开对应代码仓终端再次执行 `git status` 检查多出了什么文件。
   - 正常完成后，所有发现按严重级别（`blocker` 阻断 / `major` 重要 / `minor` 次要）排序，并优先展示绿色 **「已查证（verified）」** 标签（插件已对照本地源码逐字核验过）；标记为 **「推断（inferred）」**（含证据未通过降级原因）或 **「假设（assumption）」** 的条目需要由你人工复核。
   - 对每一条发现点击 **「采纳」**（随后去改 `spec.md`）或 **「忽略」**，系统会记录到本地 `.pmspec/metrics.jsonl` 帮助评估工具效果。

## 第五步：创建不可变快照与对比版本差异

当 `spec.md` 修改完成、校验 0 错误且准备提交跨团队评审时，先固化一份快照。

1. **清理敏感信息提醒**：发布前（快照/发布阶段），规则 `PMS-L023` 会把正文中的真实手机号、校验通过的 18 位身份证号和银行卡号直接判为 **错误（error）** 拦截；遇到此类提示请先改成脱敏样例（例如 `138****1234`）再保存。
2. **在哪操作**：右侧「需求中心」→ 规格详情页 → 切换到 **「快照」** 页签。
3. **怎么点**：点击 **「保存评审快照」**。
4. **看到什么算成功**：
   - 在 `.pmspec/snapshots/<规格ID>/` 下生成不可变快照 `v<version>.md` 与清单 `v<version>.json`，页面快照列表中多出当前版本记录（例如 `v3`）。
   - 如果当前版本号已经存在内容不同的旧快照，系统会提示 `E_SNAPSHOT_VERSION_EXISTS` 并给出 **「版本号 +1」** 按钮；点击「版本号 +1」将头信息升为 `v4` 后再点「保存评审快照」即可。
5. **查看版本差异（Diff）**：
   - 在「快照」页签的版本对比区，选择起始版本（如 `v2`）和目标版本（如 `v3`），即可查看 **新增条目 / 删除条目 / 修改条目** 以及每个条目内部逐行增删高亮对比。

## 第六步：确认分享网关配置并发布网页评审链接

### 6.1 自动共享宿主分享网关（通常无需重复配置）

- 如果你已经在 **LKL-PMStudio「设置 → 成果物 / 技能共享 → 自托管分享网关」** 配置过网关地址和访问令牌，「需求中心」会**自动继承并共享宿主的分享网关地址、认证模式（含内网无鉴权 `none`）与 Bearer 令牌**，无需在需求中心重复输入。
- 在右侧 **「需求中心」** 面板点击 **「网关设置」** 可查看当前状态：
  - 若已继承宿主配置，状态卡片会显示 **「配置来源：共享宿主分享网关」**，直接点击 **「测试连接」** 确认显示 **「连接正常」** 即可。
- 如宿主尚未配置、或你需要仅为需求中心临时使用另一套网关与令牌：
  1. 在「需求中心 → 网关设置」的「独立覆盖配置（可选）」填写网关地址并点击 **「保存地址」**（或到 **「设置 → 插件 → 需求中心 → 分享网关地址」** 修改）；
  2. 如需鉴权令牌，在下方粘贴 Bearer Token 并点击 **「保存令牌」**（仅保存在系统安全密钥库，不写入工作区文件）；
  3. 日后想恢复继承宿主配置时，点击 **「恢复共享宿主配置」** 即可清除插件独立覆盖。

### 6.2 发布评审链接

1. **在哪操作**：右侧「需求中心」→ 规格详情页 → 切换到 **「评审」** 页签。
2. **怎么点**：选择要发布的快照版本（例如 `v3`） → 点击 **「发布评审链接」**。
3. **看到什么算成功**：
   - 规格头信息的 `status` 自动更新为 `in-review`。
   - 面板生成一条包含密钥的评审链接，例如：`https://share.example.com/r/q7Zk3VbN0pW2xYfA9cLm1g?k=Hn4tW0bq8Kc2ZpLx7RyV1mD9sJfQ3aE6uGh5NiOkT2w`。
   - 点击 **「复制链接」** 发给研发、测试、风控等受邀评审人。**注意**：链接即访问凭据，切勿发到无关公开群；如不慎转发，可在面板点击 **「轮换评审密钥」** 立即作废旧链接。

### 6.3 评审人如何在网页端操作（可转发给研发/测试同事）

1. 评审人无需安装任何软件，在电脑浏览器打开收到的评审链接即可查看完整排版、状态机表格和较上一版本的变更统计。
2. 评审人可直接在任意需求或章节下方填写：**姓名、角色（产品/研发/测试/业务/风控/其他）、意见类型（问题/建议/疑问）、意见内容** 并提交。
3. 评审人在页面顶部的 **签核区** 选择姓名、角色和结论（**通过** 或 **需修改**）提交；如后续意见已修复，同一人同一角色可再次提交「通过」覆盖为最新结论。

## 第七步：同步意见、逐条闭环并标记为已批准

1. **同步网页意见**：
   - 只要右侧「需求中心」面板保持打开，系统每 60 秒自动拉取一次新意见；你也可以在「评审」页签随时点击 **「同步意见」** 按钮（或命令面板运行 `需求中心：同步评审意见`）立即刷新。
2. **逐条处理意见**：
   - 在桌面端「评审」页签中查看每条来自网关的意见，按情况操作：
     - 已按意见改好 `spec.md`：点击 **「标记为已解决」**，可附带填写解决说明（如“已在 v4 补充 REQ-004 主动查询”）；
     - 经协商暂不调整：点击 **「暂不修复」**（此时**必须填写说明原因**）；
     - 需要重新讨论：可对已关闭意见点击 **「重新打开」**。
3. **修改规格并迭代新版本（如需要）**：
   - 只要你在 `spec.md` 中修改了哪怕一个字，面板「评审」页签就会提示 **「规格已修改，当前文件与已发布快照不一致，需发布新版本」**。
   - 点击 **「版本号 +1」**（头信息自动变为 `version: 4`、`status: draft`）→ 回到「快照」页签保存新快照 `v4` → 再点击「发布评审链接」。系统会自动关闭旧版本 `v3` 的评审，并在新版网页顶部标出较 `v3` 的增删改统计。
4. **标记为已批准（定稿）**：
   - 同时满足以下全部条件时，「评审」页签的 **「标记为已批准」** 按钮才会变为可点击：
     1. 当前 `spec.md` 内容与已发布的最新快照完全一致（未再做未发布修改）；
     2. `pmspec.json` 的 `requiredSignoffRoles` 中规定的每一个必需角色最新签核均已为 **「通过（approve）」**；
     3. 所有类型为 **「问题（issue）」** 的意见均已解决或标记暂不修复（未解决数为 `0`）；
     4. 文档中不存在未关闭的 `[open]` 待决问题（`PMS-L018`）和 `[假设]` 需求（`PMS-L020`）。
   - 点击 **「标记为已批准」**。
   - **看到什么算成功**：`spec.md` 头信息自动变为 `status: approved`，网关上的评审页面立即关闭并显示「评审已关闭，仅可查看」。此时即可把定稿文本导出或复制到飞书文档 / Confluence 归档。

## 全部 19 个桌面端错误码排查指南

遇到面板提示以下错误码时，按表中对应操作处理即可：

| 错误码                      | 触发原因                                                                          | 面板显示提示                                                        | 面板按钮                 | 产品经理处理步骤                                                                                                                                           |
| --------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `E_NO_WORKSPACE`            | 当前未选中或聚焦任何工作区                                                        | 请先在左侧选择一个工作区                                            | 无                       | 在 LKL-PMStudio 左侧边栏点击一个本机文件夹或仓库后，重新打开右侧「需求中心」面板                                                                           |
| `E_REMOTE_HOST`             | 当前工作区位于 SSH 远程主机或远程容器（`ssh:` / `runtime:`）                      | 需求中心 v1 仅支持本机工作区                                        | 无                       | 在左侧边栏选择位于你本机磁盘上的规格工作区；v1 暂不支持远程主机工作区                                                                                      |
| `E_PMSPEC_INVALID`          | 工作区根目录的 `pmspec.json` 格式、必填项或字段值不合法                           | `pmspec.json` 第 `<字段>` 项无效：`<原因>`                          | 打开 pmspec.json         | 点击 **「打开 pmspec.json」**，按提示的字段和原因修正 JSON（注意引号、逗号和 `requiredSignoffRoles` 枚举）后按 `Cmd/Ctrl + S` 保存                         |
| `E_SPEC_ID_INVALID`         | 新建需求时输入的需求 ID 不符合命名规则                                            | 需求 ID 需为 2～64 位中文、字母、数字、- 或 _（不能以 - 或 _ 开头） | 无                       | 使用 2～64 位中文、字母、数字、`-` 或 `_`（不能以 `-`/`_` 开头或含空格/符号），例如 `商户自助退款`、`refund-v2` 或 `PAY-REFUND-001`                        |
| `E_SPEC_EXISTS`             | 新建规格时 `specs/<ID>/` 目录已经存在                                             | 规格 `<ID>` 已存在                                                  | 打开该规格               | 如需继续编辑原规格直接点击 **「打开该规格」**；如要新建另一份需求，更换一个新的规格 ID                                                                     |
| `E_LINT_ERRORS`             | 规格仍有校验 `error` 未清零时尝试发起 AI 预检、保存快照或发布评审                 | 当前规格有 `<n>` 个错误                                             | 查看校验结果             | 点击 **「查看校验结果」**，逐条点击错误跳转行号并按修复建议修改，直到状态栏显示 `0 错误`                                                                   |
