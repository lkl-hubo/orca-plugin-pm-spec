# ADR-001：需求中心（PM Spec Hub）v1 范围边界与延迟项

- 状态：已确认
- 基线日期：2026-11-21
- 关联文件：`src/shared/pmstudio-config.ts`、`src/shared/pmstudio-product-gates.test.ts`

## 背景

产品团队目前以自由文本撰写 PRD，结构缺失（缺验收标准、状态机死胡同、终态可回退、待决问题未关闭）与存量代码理解偏差往往在研发联调或测试阶段才暴露，导致多轮返工与内网评审往返。PMStudio 需要引入结构化规格校验、AI 现状感知预检与轻量网页评审回流能力，但首期必须聚焦“写清楚、查得实、评得顺”的最小闭环，避免范围失控影响按期上线。

## 决策

### 1. v1 纳入范围（F1–F6）

| 编号 | 能力                 | 交付边界                                                                                                                                                         |
| ---- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1   | 结构化规格格式 v1    | `spec.md` = YAML 头信息 + 7 个必需章节 + 稳定锚点（`REQ-xxx` / `AC-xxx-xx` / `Q-xxx`）+ `pmspec-states` 状态机块 + `pmspec-events` 埋点块 + `@code` 代码证据引用 |
| F2   | 确定性校验引擎       | 24 条纯函数规则（`PMS-L001` 至 `PMS-L024`），不调用大模型，2,000 行规格 P95 ≤ 150 ms（M1）                                                                       |
| F3   | AI 现状感知预检      | 在本机规格工作区拉起已启用智能体只读分析关联业务代码仓，输出 `findings.json`，插件确定性核验证据原文                                                             |
| F4   | 不可变评审快照与差异 | 生成只读快照 `v<version>.md` 与清单 `v<version>.json`，提供版本间条目级与行级差异                                                                                |
| F5   | 网页评审与意见回流   | 发布到内网自托管分享网关，评审人凭 `/r/:slug?k=<reviewerKey>` 免安装批注与签核，桌面面板增量拉取并逐条关闭                                                       |
| F6   | 评测与门禁           | 1 份干净样本与 20 份缺陷注入变体、Gate 5 产品门禁、AI 预检离线评测与 4 周试点度量采集                                                                            |

### 2. 保持 `integrations` 设置页隐藏（2026-11-21 用户裁决）

- 保持 `src/shared/pmstudio-config.ts` 中 `PMSTUDIO_HIDDEN_SETTINGS_SECTIONS` 的 `'integrations'` 项不变，并继续由 `src/shared/pmstudio-product-gates.test.ts` Gate 3 强制守护。
- 决策依据：需求中心 v1 全部流程（F1–F6）均不读取 Jira 或 Linear 凭证；若在 v1 提前放开 `integrations`，会引入与当前规格主链路无关的外部系统鉴权面与用户配置困惑。待 v2 启动需求拆单映射时，再评审是否放开该页签或构建 PM 专用集成面板。

### 3. 明确不做与 v2 延迟项

| 延迟项                       | 不纳入 v1 的原因                                                                                       | v2 接入方式                                            |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| Jira / Linear 拆单与状态同步 | 依赖 F1 的 `REQ`/`AC` 锚点格式在试点中稳定；上游 `src/main/jira` 与 `src/main/linear` 已具备客户端能力 | 基于稳定的 `REQ-xxx` 条目生成研发 Issue 草稿并回填链接 |
| Spec Drift（PR 偏离预警）    | 语义比对误报率高，缺少真实 AC 语料标定阈值                                                             | v1 试点积累真实规格与评审数据后再独立立项              |
| 可交互原型一体化             | 需要企业内部组件库元数据开放给模型调用，复杂度高                                                       | 独立立项                                               |
| 实时多人协同编辑             | 与“单一负责人编辑 + 网关只读页面批注”协作模型直接冲突                                                  | 不计划支持                                             |
| 远程主机（SSH / WSL）工作区  | v1 插件 Worker 仅直接读写本机文件系统；遇到 `ssh:` / `runtime:` 工作区时明确提示 `E_REMOTE_HOST`       | 将纯校验核心打包为随技能包下发远程主机的 CLI 执行      |

## 影响与退出策略

- 范围收敛使首期工程量控制在 37.5 人日内（阶段 0 至阶段 3），并确保桌面端和网关均可独立回滚。
- 试点止损条件：4 周试点结束后，若“评审轮次”未下降且“AI 预检有效率”低于 20%，则将 F3 降级为可选工具，仅推广 F1、F2、F4、F5。
